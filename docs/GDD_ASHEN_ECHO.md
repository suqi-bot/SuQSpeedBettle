## 0. 一页速览

**一句话定位**：用 384×216 的低分辨率像素质感，做一款“手感爽、读图快、构筑深”的第一人称 Roguelike——每局潜入一座名为“井”的下沉结构中的一章，穿过 5 层程序化地形，在 Boss 门前完成 Build 成型。

**操作一句话**：左键射击、**右键释放该武器专属技能**、Q 近战快扫、Shift 冲刺；每把枪都自带一个解题手段（§4.3.6）。

**三根支柱**

1. **像素即玩法**：低分辨率不只是滤镜。敌人剪影、攻击前摇的颜色分段、地面材质在 3 段光照下的明度差，都在为"0.3 秒内读懂战场"服务。
2. **两层构筑**：局内（武器 + 词条 + 插件 + 遗物 + 祭坛增益）解决"这一局怎么打"；局外（记忆树 + 角色 + 武器族入库 + 契约）解决"下一局从哪里开始"。
3. **风险显性化**：每一层的支路都用**明码标价的代价**换收益（血、时间、零件、视野），玩家永远知道自己在赌什么。

**核心循环（单局 40–55 分钟）**

```
选择章节 → 起始装备/角色 → [层1 → 层2 → 层3 → 层4 → 层5]（每层：探索 → 目标 → 风险选择 → 下潜）
        → 前庭备战（用零件加固） → Boss 关（3 阶段） → 结算（回响/零件转化/解锁） → 记忆树 → 下一局
```

## 1. 整体定位与核心循环

### 1.1 产品定位

| 维度 | 定义 |
| --- | --- |
| 目标玩家 | 喜欢 Gunfire Reborn / Roboquest / Delver / DUSK 的玩家；喜欢"快节奏 FPS + 构筑"但排斥 60 分钟以上的长局 |
| 情绪目标 | 前 8 分钟建立"我枪法不错"，前 25 分钟建立"我的 Build 有点东西"，Boss 战建立"我在用构筑解题" |
| 差异点 | 市场上"第一人称 Roguelike"多为卡通 3D 或写实 3D；"像素 FPS"多为纯动作射击无构筑。本项目把**像素可读性**与**深构筑**绑定 |
| 不做什么 | 不做联机、不做开放世界、不做剧情演出密集型叙事、不做像素但对 3D 无信息价值的"贴图复古" |
| 难度基线 | 默认难度下，首次通关章1 约需 4–6 局；技能型玩家可在 2 局内通过 |

**参考坐标**

- 场景/节奏：Delver（第一人称像素地牢）、DUSK（高速 FPS 手感）、Strafe（像素 FPS 的视觉语言）
- 构筑/词条：Gunfire Reborn（武器词条）、Roboquest（武器 + 角色技能耦合）
- 章节/Boss：Hades（关卡-祝福- Boss 的三段递进）、Enter the Gungeon（房间风险房）

### 1.2 第一人称像素风格的具体表现方式

#### 1.2.1 渲染管线（核心技术方案）

| 环节 | 规格 | 目的 |
| --- | --- | --- |
| 内部分辨率 | 默认 **384×216**（可选 320×180 / 480×270） | 3D 场景以极低像素密度渲染，天然产生"像素块" |
| 放大 | 整数倍最近邻（1080p → 5×=1920×1080），非整数分辨率用整数倍 + letterbox | 杜绝半像素抖动、摩尔纹 |
| 色板 | 每章 **32 色专属 + 16 色共享**（皮肤/UI/通用），全游戏 ≤ 48 色同屏 | 章节辨识度 + 统一性 |
| 贴图 | 32×32 主材质量级，64×64 仅用于 Boss/标志物；每米 8 texel；无 mipmap 以外的过滤 | 像素密度与分辨率匹配，不出现"高清贴图糊成一片" |
| 光照 | 顶点色 **3 段 ramp（暗/中/亮）** + 硬阴影（256 shadow map） | 分档光照让体积在低分辨率下仍可读 |
| 雾效 | 屏幕空间 **4×4 Bayer 抖动** 的色阶雾，不用平滑渐变 | 像素风格化的空气感，且能让远处敌人"沉入"背景 |
| 法线/高光 | 关闭 specular；用 **banded rim light**（1px 亮边）分离轮廓 | 低分辨率下高光会变成噪点 |
| 敌人 | **8 方向 billboard 精灵**（32×48 ~ 64×96），2px 深色描边 | 剪影优先，保证"一眼识别敌人类别" |
| 武器视图 | **纯 2D 像素精灵**（屏幕空间），128×96，每个动作 3–5 帧；无 3D 模型 | 第一人称武器的“像素手工感”，同时降低制作成本 |
| 后处理 | 仅：色板量化、抖动雾、受击红闪（2 帧）、低血量去饱和 | 拒绝 bloom / 运动模糊 / 景深 |
| 相机 | FOV 82（可 75–90），**像素对齐的整数位移抖动** | 屏幕抖动不产生亚像素撕裂 |
| 性能目标 | 1080p / 60fps，Draw Call ≤ 300，三角面 ≤ 250k，同屏敌人 ≤ 12 + 弹幕 ≤ 32 | 保证主机移植与低配可玩 |

#### 1.2.2 三套风格方案对比（决策记录 D-01）

| 方案 | 表现力 | 手感/碰撞 | 美术成本 | 风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. 真 3D 低模 + 低分辨率渲染（推荐） | 高（可做高低差、垂直关卡） | 精确（真实碰撞体） | 中（低模 + 低分辨率贴图） | 低 | **采用**：唯一能同时满足"第一人称纵深感"和"可读性"的方案 |
| B. 2.5D 全 billboard（Doom 式） | 中（伪 3D 纵深） | 差（无法做真正的垂直与斜坡） | 低 | 高（关卡设计受限，玩家会感知"纸片"） | 仅用于敌人与装饰物 |
| C. 体素世界（Teardown 式） | 高（可破坏） | 中（体素碰撞手感偏"格"） | 高（体素美术工具链缺失） | 中 | 不采用：可破坏不是核心卖点，成本不可控 |

> **混合策略（最终定案）**：世界几何 = A（低模 + 低分辨率贴图 + 3 段光照）；敌人与植被 = B（8 方向 billboard）；**武器 = 纯 2D 屏幕空间精灵（不做 3D 模型）**。三者共用同一色板与像素网格，因此视觉统一。

#### 1.2.3 像素可读性规则（美术硬约束）

1. **剪影优先**：任何敌人缩到 32×32 后，剪影必须与其它敌人可区分（测试：黑白剪影辨识率 ≥ 90%）。
2. **身份双色原则**：每个敌人只用 2 个身份色（例如章1 锈壳鼠 = 锈橙 + 暗褐），其余为环境灰阶。
3. **攻击前摇必须有颜色事件**：蓄力时身上出现 1 个高饱和色块（0.35s 内可见），这是玩家唯一的"预警语言"。
4. **地面材质与可交互物明度差 ≥ 3 级色阶**，避免低分辨率下"踩到陷阱才发现"。
5. **禁止亚像素运动**：所有贴图/精灵在屏幕上按整数像素移动（渲染层做 pixel snapping）。

#### 1.2.5 第一人称武器：纯 2D 像素精灵（决策记录 D-09）

武器本体不做 3D 模型，全部以**屏幕空间 2D 精灵**呈现（DUSK / DOOM 传统）。这是成本与风格的双重最优解。

| 项 | 规格 |
| --- | --- |
| 画布 | 128×96（屏幕坐标系），锚点固定于屏幕右下/下方 |
| 像素对齐 | 整数像素位移；后坐 = 向上 3–6 px + 上旋 ±2°（仅视觉，不改变射弹方向） |
| 动作集 | 待机 2 帧（呼吸）・射击 2–3 帧・换弹 4–6 帧・切枪 2 帧・冲刺 1 帧・近战 3 帧 |
| 帧率 | 射击 12–15 fps；换弹 8–10 fps；待机 4 fps；**故意不插值** |
| 层序 | 手臂/枪体 → 枪口焰（独立 2 帧层）→ 弹壳（可选粒子） |
| 品阶表现 | 同族共享精灵，**只换调色板**（粗制降饱和 / 回响加 1 px 发光边），不重画 |
| 开镜 | 2D 变焦 + 像素遮罩（非 3D 镜头 FOV），边缘用黑边/准星框遮挡 |
| 摆动 | 行走摆幅 2 px/步，呼吸 1 px/1.2s；开火时锁定摆动 0.12s |
| 着色 | 仅 3 级色阶 + 1 级高光，与场景光照同步做个简单的 3 级亮度映射（不实时受光） |
| 制作量 | 24 族 × 平均 18 帧 = **≈432 张精灵**（占总量不到 1/3 个角色的动画量） |

**为什么不做 3D 武器模型**

| 维度 | 2D 精灵（采用） | 3D 模型（放弃） |
| --- | --- | --- |
| 风格一致性 | 与像素风完全一致，天然无锯齿 | 低模在 384×216 下容易“多边形感过强” |
| 制作成本 | 432 张精灵 = 约 1.5 人月 | 24 个模型 + 骨骼动画 + 手部绑定 ≥ 5 人月 |
| 手感调优 | 改 1 帧即可改后坐手感 | 需回到 DCC 重导出 |
| 局限 | 无法做真实的武器摆动/遮挡/双持动态 | 可做但本作不需要 |

> **衔接影响**：武器精灵也是**收藏界面/图鉴**的唯一视觉资源（同一张精灵放大 2× 展示），因此不额外制作立绘；这也是选 2D 精灵的重要原因之一。

### 1.3 单局核心循环

**标准模式「单章突入」**（默认，40–55 分钟）

```
[局外] 选章节 / 角色 / 起始武器族
   ↓
[层1] 入境：低压力教学层，2 个宝箱，0 精英
   ↓
[层2] 分流：出现第一个分支路线与精英
   ↓
[层3] 竖井：垂直度提升，第一个"风险房"强制出现
   ↓
[层4] 贪欲：双精英 + 双风险房，产量最高的一层
   ↓
[层5] 前庭：Boss 前最后一层，商店/修复/加固
   ↓
[Boss 关] 3 阶段，阶段间 3s 补给窗口
   ↓
[结算] 战利品折算 → 回响（局外货币）→ 记忆树 → 解锁新内容
```

**分段时间预算**

| 段落 | 时长 | 设计目的 |
| --- | --- | --- |
| 层 1–2 | 12–14 min | 建立手感与第一个 Build 雏形（保证 2 小时内必出 1 件稀有武器） |
| 层 3–4 | 14–16 min | Build 成型期，出现"取舍型"抉择（升级 / 换枪 / 赌词条） |
| 层 5 + 备战 | 7–9 min | 资源结算、Boss 前的策略窗口 |
| 层间（购物/熔铸/加载） | 3–5 min | 把「拾取」变成「构建」 |
| Boss 关 | 3–5 min | 构筑验证 + 操作考试 |
| 结算 | 1–2 min | 目标感闭环（本次跑分、解锁进度、下一步目标） |

### 1.4 局外成长与重玩驱动

**驱动四层**

| 层级 | 内容 | 玩家感受 |
| --- | --- | --- |
| 内容解锁 | 新武器族、插件、遗物入库、角色、章节 | "下一局会遇到没见过的东西" |
| 起始配置 | 起始武器族选择、初始插件、携带 1 个遗物 | "我可以用不同方式开局" |
| 难度契约 | 5 级契约（敌人词条、环境恶化、限制） | "我变强了，所以我要更难的题" |
| 记录与目标 | 每章最快通关、无伤 Boss、100% 图鉴 | "我还差一点" |

**明确不做“纯数值成长”**：**内容型记忆树**中没有任何无条件数值节点，永久成长只体现在**选项**与**便利**（如“初始护甲 +20”“重铸折扣”）；独立的**角色天赋（精通线）**只提供**条件性加成**（如“冲刺后 2 s +10% 伤害”）与少量容错（+10 最大 HP），避免变成线性数值碾压。理由见 §7.3。

**记忆（局外货币）获取**

| 来源 | 数量 | 备注 |
| --- | --- | --- |
| 击杀 Boss（首次） | 300 | 首杀额外 +200 |
| 击杀 Boss（重复） | 120 | 防止"刷首杀" |
| 精英击杀 | 8 | 每章 6–8 只 → 48–64 |
| 风险房完成 | 25 | 每章 4–6 个 |
| 每层通关基础 | 15 | 5 层 = 75 |
| 全清加成（无死亡） | 60 | 鼓励完整探索 |

## 2. 章节系统

### 2.1 章节设计原则

1. **一章一个"动词"**：每章新增一个玩家必须学会的动作/概念（章1 空间走位 → 章2 光暗取舍 → 章3 垂直机动 → 章4 节奏闪避），且该动词会被 Boss 战强制考试。
2. **机制可复用于武器/敌人/地形三者**：例如章1 的"压力"既是环境伤害、也是敌人强化条件、也是武器词条（"对高压目标 +25% 伤害"）。
3. **配色即导航**：每章 32 色中固定 4 色用于"危险/可交互/可破坏/出口"，全章一致，跨章仅色相变化。

**机制递进关系（不重复、可叠加）**

```

章4 = 节奏（时间/摆动/重组）：把前 3 章的"空间-资源-垂直"压缩成"时间轴问题"
```

> 设计意图：章4 不是"更难的章3"，而是**把前三章的机制抽象成时间维度**。例如章3 的"垂直攀爬"在章4 变成"摆锤周期内的窗口移动"。

## 3. 章节内关卡结构

### 3.1 层级角色定义

每章固定 5 层 + 1 Boss 关。5 层不是"同一张地图换皮"，而是**五个功能层**：入境 → 分流 → 竖井 → 贪欲 → 前庭。功能层决定了房间配额、敌人配额、机关密度和可选路线形态，让玩家在每章的第 1 分钟就能预判"这一层会给我什么"。

| 层 | 功能 | 玩家目标 | 心理曲线 |
| --- | --- | --- | --- |
| 1 | 入境 | 熟悉本章配色/机制，拿到第一件武器 | 安全 → 好奇 |
| 2 | 分流 | 首次路线取舍（主路径 vs 支路精英） | 开始计算收益 |
| 3 | 竖井 | 机制加压 + 垂直挑战（本章机制的"教学关"） | 轻微紧张 |
| 4 | 贪欲 | 双精英 + 双风险房，产量最高 | 兴奋与危险并存 |
| 5 | 前庭 | 资源结算、商店、Boss 前加固 | 收束、备战 |

### 3.2 地形生成规则

#### 3.2.1 基础参数

| 项 | 数值 |
| --- | --- |
| 网格单元 | 2.0 m × 2.0 m |
| 地图尺寸 | 48 × 48 格（96 × 96 m），可用区约 70% |
| 房间尺寸 | 5×5 ~ 12×12 格（10×10 ~ 24×24 m），战斗房不小于 7×7 格 |
| 走廊宽度 | 2 格（4 m），主路径关键段 3 格（6 m） |
| 高度层 | 0 / 2.5 / 5.0 m 三级（章3 起可出现 7.5 m 的竖井） |
| 连接方式 | 坡道（坡度 1:3）、梯子（垂直 2.5 m 内）、藤蔓/升降（章3–4） |
| 跳跃能力约束 | 起跳高度 1.10 m、水平跨越 2.5 m、冲刺跨越 4.0 m → **所有主路径必需跨越 ≤ 2.5 m** |

#### 3.2.2 生成流水线（7 步）

```
① 种子派生     run_seed → chapter_seed → floor_seed → 5 条独立子流
② 房间撒点     Poisson Disk（最小间距 6 格），目标房间数由层参数决定
③ 图构建       Delaunay 三角 → MST（主路径）→ 回填 18–25% 环路边
④ 房间定角色   起点 / 出口 / 战斗 / 精英 / 资源 / 风险 / 秘密 / 事件 / 枢纽（按配额表）
⑤ 走廊开挖     A* 连接，2 格宽，拐角做 45° 切角，门框统一 4×3 格
⑥ 垂直塑形     每房间独立标高 0/2.5/5.0，坡道或梯子连接，禁止"无工具的直接落差 > 2.5 m"
⑦ 摆件与验证   手工房间模板套用 → 机关/掩体/敌人点位 → 连通性/可达性/配额三重校验
```

#### 3.2.3 随机种子与随机性控制

| 机制 | 实现 | 目的 |
| --- | --- | --- |
| 种子派生 | `chapter_seed = hash(run_seed, chapter)`；`floor_seed = hash(chapter_seed, floor)` | 同一次跑图可复现、可分享、可回放 |
| 独立子流 | 地图 / 掉落 / 敌人 / 事件 / 装饰 **各用一条 PRNG 流** | 玩家重掷某个宝箱不会影响地图；调试可单独复现 |
| 软约束（保证项） | 每层保证：1 条主路径 + ≥2 条环路、1 个秘密房、层1/3/5 各 1 个商店（层5 有 2 个）、首房间无敌人 | 防止"随机出烂图" |
| 配额表 | 每层房间角色配额固定（战斗 55%、资源 15%、风险 10%、秘密 8%、事件 7%、枢纽 5%） | 保证体验方差在可控范围 |
| 校验失败回退 | 连通性/可达性失败 → `floor_seed + 1` 重生成，最多 8 次 → 仍失败则套用该层的**手工保底布局** | 零软锁 |
| 敌人出生规则 | 距玩家入口 ≥ 12 m；不与玩家同房间；出生点必须有 ≥ 1.5 m² 站立空间 | 避免"开门被打脸" |

#### 3.2.4 地形要素与高低差

| 要素 | 出现章 | 玩法作用 |
| --- | --- | --- |
| 双层货架 / 天桥 | 全章 | 垂直射击位，敌人会占据高点 |
| 可破坏掩体 | 全章 | HP 80–150，破坏后改变掩体格局 |
| 深坑 / 排水口 | 章1、章4 | 掉落 15 伤害并传送到本层起点（非死亡） |
| 移动平台 | 章3、章4 | 定期移位，制造"窗口式"通路 |
| 单向门 | 全章 | 只可从一侧打开，形成回环与"回头成本" |
| 竖井 | 章3、章4 | 2 层高（5 m）垂直战斗空间，跌落有伤害 |

> **高低差约束**：单个战斗房内高差 ≤ 2.5 m（玩家可一次跳跃 + 冲刺解决），且高点必须提供**至少两条**下撤路线，避免"上去就被围死"。

#### 3.2.5 每层主题差异（同章内的变化）

每章 5 层共用色板与材质，但通过**三个变量**产生差异：

**副目标（每层随机展示 1 个，完成则本层战利品品质 +1 档）**

| 副目标 | 条件 | 奖励 |
| --- | --- | --- |

### 3.5 可选路线与风险回报设计

每层地图上从起点到出口存在 **1 条主路径 + 2–4 条支路**。支路末端固定放置高价值内容，形成"要不要绕"的抉择。

| 风险房类型 | 代价 | 回报 | 推荐出现章 |
| --- | --- | --- | --- |
| 背叛者祭坛 | 支付当前 HP 的 30% | 随机遗物（品质 +1 档） | 全章 |
| 限时净化 | 90 s 内清 3 波共 18 敌 | 高品阶武器 1 件 + 200 零件 | 章2+ |
| 深渊裂隙 | 直接跳下层，放弃本层剩余房间 | 获得"深渊印记"（下局 +1 起始遗物） | 章3+ |
| 赌徒箱 | 3 选 1，其中 1 个是诅咒（负面词条） | 2 个高价值（插件/遗物/稀有武器） | 全章 |
| 无光区 | 敌人属性 +30% | 掉落率 +50%、画面近乎全黑 | 章2+ |
| 竞技场 | 连续 2 波精英（无敌方增援） | 插件 + 回响 40 | 章3+ |
| 钟摆回廊 | 通过 3 段移动平台（失败不掉血但耗时） | 隐藏房钥匙 | 章4 |

**风险回报的量化原则**

1. 每个风险房的**期望收益 ≥ 主路径同时间收益 × 1.8**，否则玩家不会选。
2. 代价必须**可支付**：血量代价不超过当前 HP 的 30%，时间代价不超过 90 s。
3. 风险房入口处**必须能看清代价**（3D 图标 + 文字），不做"进去才知道"。
4. 一局内风险房总数上限 7 个，避免"全赌博流"成为最优解。

**层间撤离（Push-your-luck）**

| 行为 | 结果 |
| --- | --- |
| 层间主动撤离 | 已获战利品 100% 折算记忆，但没有 Boss 奖励，不解锁章节 |
| 死亡 | 已获战利品 35% 折算记忆（保底 40） |
| 击败 Boss | 全额结算 + 首杀奖励 + 章节解锁 |

> 这给了"Build 崩了"的玩家一条体面的退出路径，同时保证"硬闯 Boss"永远是更优的期望值（约 1.6×）。

### 3.6 难度递增与节奏控制

**每层内部的节奏波形（单层 7 分钟）**

```
0:00  入场（安全 20s，环境音建立）
0:20  第一场小战斗（3–4 敌，无精英）        ← 热身
1:30  探索 + 拾取（30–60s 无战斗）           ← 呼吸
2:30  中战斗（5–6 敌 + 1 个机制联动）        ← 压力
4:00  分支抉择（主路径 / 支路）              ← 决策
5:00  精英战 或 风险房                       ← 峰值
6:20  收尾（残余敌人 / 取核心）              ← 释放
7:00  下潜                                 ← 结算
```

**递减式信息给予**：每层第一个战斗房必须是"教学式遭遇"——只出 1 种敌人 + 1 个环境机制，让玩家在本层学到"这一层在玩什么"。

**反重复机制**：连续 2 层不出现同一种精英词条；同一敌人族群在相邻两层最多出现 2 次；风险房类型 3 层内不重复。

## 4. 武器配置

### 4.1 设计原则

1. **一个武器 = 一种节奏**：不是“伤害高低”的差异，而是“开火节奏 / 站位要求 / 资源压力”三种约束的组合。
2. **没有全能武器**：每把武器都有至少一个“场景下明显变弱”的硬条件（距离、护甲、移动、弹药）。
3. **环境可被武器利用**：爆炸能炸掩体、激光能点孢子云、蒸汽枪能把敌人推进水里——武器与章节机制必须至少有一个交叉点。
4. **首发 24 族，不靠数量靠组合**：24 族 × 6 品阶 × 36 词条 × 16 插件 ≈ 8.3 万种理论组合，实际有效构筑 5 类。
5. **每把枪都要有“一键高潮”**：左键负责输出，右键技能负责制造“这把枪值得记住”的瞬间（§4.3.6），两者共同决定这把武器的身份。

### 4.2 类别划分与定位

#### 4.3.6 右键武器技能（Alt-Fire）系统

**定位**：左键是“稳定输出”，右键是“这把枪的解题手段”。每把武器都有且只有一个专属技能，用来制造记忆点、提供应对章节机制的钥匙，并让同一把枪在不同构筑里有不同的开火节奏。

**全局规则**

| 项 | 规则 |
| --- | --- |
| 输入 | 左键射击 / **右键技能**；手柄 RT 射击 / LT 技能 |
| 冷却 | 4–15 s（均值 9 s），**无全局 GCD**；切枪不共享 CD（CD 记在武器实例上） |
| 充能型 | 最多 2 层（蜂巢无人机/集束雷），每层独立冷却 |
| 额外消耗 | 部分技能额外扣弹药/热量/回响（表中标注） |
| 空放 | 需要目标的技能（如吞噬）无目标时不进 CD；范围/位移类必进 CD |
| 打断 | 技能可被冲刺/换弹打断（标“霸体”者除外）；技能中受击不中断 |
| 对 Boss | 控制效果 ×0.3；Boss 每 8 s 免疫控制 1 次；击飞无效 |
| 无敌 | 位移类技能自带 ≤ 0.3 s 无敌帧，不可叠加 |
| 误触保护 | 右键需按住 ≥ 0.06 s 才触发，防连点误放 |
| 数值上限 | 技能对总 DPS 的贡献 **≤ 25%**（§4.11） |

### 4.11 平衡性设计

**DPS 预算公式**

```
有效 DPS = 单发伤害 × 命中数 × 射速 × 品阶系数 × (1 + 词条加成) × (1 + 增益加成) × 命中率
期望 DPS 目标：章1 150 / 章2 260 / 章3 400 / 章4 560
```

**右键技能对 DPS 预算的修正**

| 约束 | 数值 | 说明 |
| --- | --- | --- |
| 技能 DPS 贡献 | ≤ 基础 DPS × 25% | 以“冷却周期内的平均伤害增量”计算，不含控制/位移的间接收益 |
| 单次技能峰值 | ≤ 该武器 2.5 s 的普通输出 | 防止“攒着右键当主武器” |
| 持续增益覆盖率 | ≤ 25% | 稳定开镜 3s/12s、过载脉冲 一梭/12s |
| 控制时长 | ≤ 1.2 s（精英）/ 0.36 s（Boss） | 控制类技能 |
| 位移距离 | ≤ 5 m（平均） | 防止技能位移超越关卡设计边界 |

### 4.12 方案对比：武器系统架构（决策记录 D-04）

| 方案 | 内容 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 全随机词条（Gunfire 式） | 所有武器均随机生成 | 重玩度高、开发成本低 | 武器无记忆点，玩家记不住“那把枪” | 不单独采用 |
| B. 全固定独特（Hades 式） | 每把武器手工设计、固定能力 | 记忆点强、平衡可控 | 重玩深度低，20 小时后无新鲜感 | 不单独采用 |
| C. **混合（推荐）** | 基础族固定 + 词条随机 + 回响品阶手工被动 | 既有“这把枪叫什么”的记忆点，又有“这把枪长什么样”的随机性 | 平衡工作量中等（需同时调族与词条） | **采用** |
| D. 部件组装 | 玩家自己拼枪管/机匣/弹匣 | 构筑深度最高 | 上手门槛高、UI 复杂、首作风险大 | 二期/DLC 方向 |

### 5.3 敌人与 Boss 设计原则

#### 5.3.1 五条硬原则

1. **可读先于难度**：所有攻击前摇 ≥ 0.35 s；前摇期间必须出现一个“颜色事件”（蓄光/发光/地面标记）。
2. **每个敌人一个动词**：追击 / 压制 / 封锁 / 防守 / 召唤。同一敌人不得同时具备两种以上强动词。
3. **组合要有节奏**：每波敌人 ≥ 1 个近战压迫 + ≥ 1 个远程；控制型 ≤ 2 个；同屏 ≤ 12 个。
4. **弱点必须可操作**：部位弱点（可绕后）或元素弱点（可携带），不能是“随机暴击”。
5. **死亡反馈 ≤ 0.5 s**：死亡动画短、尸体 3 s 后消失（避免遮挡视线），击杀音效统一。

#### 5.3.5 Boss 设计原则

1. **三阶段三课题**：每阶段考一个不同的能力（读前摇 / 目标优先级 / 资源与爆发），不重复。
2. **环境解**：每个 Boss 至少提供 1 个“不靠数值也能推进”的环境机制（压力阀/彩窗/花蕊/时滞场）。
3. **失败可读**：致死攻击必须是“可躲避的大招”，而不是“连续三发普攻磨死”。
4. **不禁止走位**：Boss 房永远有 1 个以上的安全区，避免“全屏毒”式无解设计。
5. **首杀与重复差异**：重复击杀时 Boss 增加 1 个随机精英词条，防止套路化。

### 5.6 存档与进度系统

#### 5.6.1 存档层级

| 类型 | 写入时机 | 内容 | 防作弊 |
| --- | --- | --- | --- |
| 运行快照（Run Save） | 每层**进入时** + 每层**结束时** | 地图种子、玩家状态、背包、层内未拾取物 | 单一槽位；退出后可继续，但**不允许回滚** |
| 局外档案（Profile） | 结算、解锁时 | 记忆、角色/武器族解锁、统计、契约 | 本地 + 云双写，带 CRC |
| 校验点 | 每次写盘 | 时间戳 + 版本号 + CRC32 | 修改后无法读取 |

> **防 Save-Scum 规则**：快照在“进入层”与“离开层”各写一次，且第二次写入会覆盖第一次。玩家中途退出只能回到“本层开始”，不会回到“进层前的商店”。这是“硬核但不残酷”的折中方案。

| 问题 | 规则 | 原因 |

### 6.2 三条主链的闭环

```
【战斗链】
敌人设计（1 动词）→ 弱点 → 玩家选武器 → 词条强化 → 遗物质变 → Boss 考试
     ↑                                                              ↓
     └────────────── 新章节机制 / 新敌人族群 ←── 解锁 ←──────────┘

【成长链】
首通章节 → 记忆 → 记忆树 → 新角色/新武器族/新插件 → 新起手 → 新构筑 → 更高契约

【经济链】
探索/风险 → 零件 → 商店/熔铸 → DPS 提升 → 能打更高层 → 更多零件/更好掉落
```

> 三条链必须在**同一局内**闭合：一局里玩家应该至少感受到 1 次“战斗链”的顿悟、 1 次“成长链”的期待、 1 次“经济链”的取舍。

### 6.3 全局数值校核表

> **实战有效 DPS 系数 = 0.50**（含命中率、走位停顿、换弹、过热等综合损耗）。

| 章 | 敌人 HP 系数 | 杂兵 HP | 玩家期望 DPS | 实战有效 DPS | 杂兵 TTK | 精英 TTK | Boss HP | Boss TTK |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | ×1.00 | 60–140 | 150 | 75 | 0.8–1.9 s | 6.1 s | 9,000 | 120 s |
| 2 | ×1.80 | 108–252 | 260 | 130 | 0.8–1.9 s | 6.4 s | 15,000 | 115 s |
| 3 | ×2.75 | 165–385 | 400 | 200 | 0.8–1.9 s | 6.3 s | 22,000 | 110 s |
| 4 | ×3.75 | 225–525 | 560 | 280 | 0.8–1.9 s | 6.2 s | 30,000 | 107 s |

**校核结论**：四章的杂兵/精英/Boss TTK 分别稳定在 0.8–1.9 s / 6.2–6.4 s / 107–120 s，说明“敌人 HP 系数”与“玩家 DPS 成长曲线”是匹配的。**任何一侧单独调整都会破坏这张表**，因此调平衡时必须以整行为单位改动。

### 6.4 一致性验收清单（设计评审用）

| # | 检查项 | 通过标准 |
| --- | --- | --- |

| 6 | 风险房期望收益 | ≥ 主路径同时间收益 × 1.8 |
| 7 | 经济是否闭环 | 单局支出率 65–75% |
| 8 | 单局时长 | 40–55 分钟（P50） |
| 9 | 记忆树解锁时长 | 8–10 小时全部解锁 |

| --- | --- |

## 7. 方案对比与取舍汇总

### 7.1 单局结构（决策记录 D-02）

| 方案 | 结构 | 时长 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. 单章突入（推荐） | 5 层 + Boss | 40–55 min | 符合现代 Roguelike 会话长度；失败成本低；内容复用率高 | 长线目标感较弱 | **主模式** |
| B. 全链深潜 | 4 章 ×（5+1） | 3–4 h | 史诗感、成长跨度大 | 失败成本过高，中途退出即前功尽弃 | 作为可选模式（需存点） |
| C. 双章 | 10 层 + 2 Boss | 90–100 min | 折中 | 不上不下，两头不讨好 | 不采用 |

> **推荐 A + 后期解锁「连锁深潜」（§6.5）**：先用短局拉新与保底体验，再用长局满足核心玩家。

### 7.2 地图生成方式（决策记录 D-03）

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 房间图 + MST + 回路（推荐） | 房间质量可控、支路结构清晰、易做风险房 | 房间内部需手搓模板 | **采用** |
| B. BSP 分割 | 实现简单、房间不重叠 | 走廊机械感强，难做“支路长短”差异 | 不采用 |
| C. 细胞自动机（洞穴） | 有机、自然 | 无法控制房间数量与战斗节奏，易出瓶颈 | 仅做“秘密洞窟”装饰层 |
| D. 纯手工模块拼接 | 品质最高 | 内容量成本爆炸 | 作为 A 的“房间模板”层（每章 40 个） |

> **实际架构 = A（宏观图） + D（微观房间模板）**。这样既保证地图多样性，又保证每个战斗房都是“设计过的遭遇”。

### 7.3 局外成长强度（决策记录 D-05）

| 方案 | 内容 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 纯内容解锁（推荐） | 只解锁武器/角色/插件/章节 | 技巧驱动、长期口碑好 | 新手前期“感觉没变强” | **采用** |
| B. 数值成长 | 永久 +伤害/+HP | 新手反馈强 | 后期难度失衡，变成“数值碾压” | 不采用 |
| C. 混合 | 90% 内容 + 10% 便利 | 折中 | 需严格控制数值上限 | 局部采用（仅 6 个受控节点，单项 ≤ +30%） |

> **理由**：Roguelike 的长期留存来自“我变强了”而不是“我的角色变强了”。数值型元进度会让契约难度失去意义。

### 7.4 存档规则（决策记录 D-06）

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 硬核 Permadeath，无中断 | 纯粹、张力强 | 现实生活不友好，差评风险 | 不采用 |
| B. 单层快照（推荐） | 可中断；不可回滚 | 需处理状态序列化 | **采用** |
| C. 随时存档 | 最友好 | 可 Save-Scum，破坏 Roguelike 核心 | 不采用 |

### 7.5 Boss 数量与复用（决策记录 D-07）

| 方案 | 成本 | 体验 | 结论 |
| --- | --- | --- | --- |
| A. 每章 1 个专属 Boss（推荐） | 基准 | 4 个高辨识度 Boss | **采用** |
| B. 每章 2 个 Boss | +80% 关卡与美术成本 | 体验提升有限（单局只会遇到 1 个） | 不采用 |
| C. 复用 + 词条变体 | 低 | 重复感强 | 仅用于契约/连锁深潜 |

> 补偿方案：重复击杀时 Boss 附加 1 个随机精英词条（§5.3.5），用低成本提供变化。

### 7.6 章节与层数规模（决策记录 D-08）

| 方案 | 内容量 | 首通时长 | 评价 | 结论 |
| --- | --- | --- | --- | --- |
| A. 3 章 × 6 层 | 18 层 + 3 Boss | 12–15 h | 章节数少，主题疲劳快 | 不采用 |
| B. **4 章 ×（5+1）** | 20 层 + 4 Boss | 18–25 h（含解锁与契约） | 主题丰富度与成本平衡点 | **采用** |
| C. 5 章 ×（5+1） | 25 层 + 5 Boss | 25–32 h | 内容量 +25%，首作风险高 | 二期扩充 |

### 7.7 武器表现形态（决策记录 D-09）

| 方案 | 内容 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 纯 2D 屏幕空间精灵（推荐） | 128×96，每动作 3–5 帧，整数像素位移 | 风格一致、成本低（≈432 张）、改手感快、可复用作图鉴 | 无法做真实武器遮挡/双持动态 | **采用** |
| B. 3D 低模武器 + 手部绑定 | 真 3D 视角模型 | 可做摆动/双持/动态光影 | 384×216 下多边形感强，成本 ≥ 5 人月 | 不采用 |
| C. 混合（近战 3D / 枪械 2D） | 按武器分类选择 | 近战锤击感更强 | 风格割裂，两套管线 | 不采用 |

> 实施细节见 §1.2.5（动作集/帧率/品阶换色/制量），内容预算影响见 §8.2。

### 7.8 鼠标右键的职责分配（决策记录 D-10）

| 方案 | 内容 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 右键 = 武器技能，取消 ADS（推荐） | 左键射击 / 右键技能；狙击开镜归入技能 | 每把枪有记忆点；手柄 LT 天然对应；多一个战术维度 | 腰射精度需单独平衡；传统 FPS 玩家需适应 | **采用** |
| B. 右键 = ADS，技能移至 E/F | 保留传统 FPS 习惯 | 上手零成本 | 技能变成“可有可无的附属键”，且与交互键冲突 | 不采用 |
| C. 右键短按 = 技能，长按 = ADS | 双功能 | 两者都能用 | 误触严重，手感不可调，测试成本高 | 不采用 |
| D. 右键 = 技能，ADS 移到中键 | 两者分离 | 不冲突 | 中键在激烈战斗中不可靠；手柄无对应键 | 不采用 |

> **为什么值得放弃 ADS**：384×216 下“精确瞄准”的收益远小于传统 FPS，且本作以 6–20 m 中近距离交火为主；把精度管理交给“移动停止 / 连射散布 / 技能窗口”，比一个镜头变焦更有构筑意义。狙击类需求用“稳定开镜”技能承接，不丢玩法。

### 8.4 主要风险与对策

### 8.5 垂直切片验收标准（Definition of Done）

1. 章1 从进入层 1 到击败铁喉可完整通关，无软锁、无崩溃。
2. 至少 8 把武器、12 条词条、4 个插件、4 个遗物可用且数值符合预算表。
3. 存档/结算/记忆树最小闭环可运行（至少 6 个节点）。
4. 30 名外部玩家测试：章1 通关率 55–70%，单局时长 40–55 分钟，P90 层时长 ≤ 8.5 分钟。
5. 帧率：1080p / 60fps，低配（GTX 1050）≥ 45fps。
